# Execution plans

A plan is written before any multi-day piece of work and kept in the repository, so the
reasoning behind the result stays findable.

- `active/` — plans in progress. One file per plan; append a dated progress log as work lands.
- `completed/` — finished plans, kept as written, with a short outcome section.
- [tech-debt-tracker.md](tech-debt-tracker.md) — known weaknesses that are not yet scheduled.

A plan states: context (why), the approach, the files touched, how it is verified, and the
risks. When it finishes, move it to `completed/` and record what differed from the plan.
